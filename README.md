# 3MTT Cybersecurity Capstone — Secure Coding Review

## Project title
**Secure Coding Review of a Web-Based Login Module**

## Purpose
This project demonstrates a defensive secure-code review of a small Flask login application. It contains an intentionally vulnerable version for a controlled local lab and a remediated version.

**Important:** Run the vulnerable application only on your own computer/lab. Do not deploy it to the public internet.

## Learning objectives
- Identify common secure-coding weaknesses in authentication code.
- Explain security impact and risk.
- Apply practical remediation.
- Compare vulnerable and secure implementations.
- Produce a professional security-review report.

## Technologies
- Python 3
- Flask
- SQLite
- Werkzeug password hashing
- Git/GitHub

## Setup
1. Create and activate a virtual environment:
   - Windows: `python -m venv .venv` then `.venv\Scripts\activate`
   - Linux/macOS: `python3 -m venv .venv` then `source .venv/bin/activate`
2. Install dependencies:
   `pip install -r requirements.txt`
3. Initialize the local database:
   `python init_db.py`

## Run the vulnerable lab
```bash
python app.py
```
Open `http://127.0.0.1:5000`

The vulnerable version is intentionally unsafe and is included only to support the code-review exercise.

## Run the secure version
Stop the first server, then:
```bash
python secure_app.py
```
Open `http://127.0.0.1:5000`

DDemo account:
- Username: `student`
- Password: The demo password generated by `init_db.py` for the local lab.

Change this password if you adapt the project for a real deployment.

## What to review
The lab demonstrates weaknesses such as:
- SQL query construction using untrusted input.
- Insecure password handling/comparison in the vulnerable implementation.
- Weak error handling that can reveal authentication details.
- Missing login-attempt throttling.
- Insecure session configuration.
- Missing security headers.
- Hardcoded application secret.

The secure version demonstrates:
- Parameterized database queries.
- Password hashing and verification.
- Generic authentication errors.
- Simple per-account login throttling.
- Secure cookie settings.
- Environment-based secret configuration with a safe development fallback.
- Basic security headers.
- Input length/format validation.
